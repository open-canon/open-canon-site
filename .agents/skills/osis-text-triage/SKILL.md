# OSIS text triage

The XML files in `open-canon-osis-documents/` are generated by the scrapers in
`src/open_canon_site/scrapers/` and rendered by the site generator. When one changes,
read what a visitor will actually see and triage anything that looks wrong.

## The driving principle: preserve the original text

The goal is a faithful copy of the source text. Odd is not the same as wrong.

- **If the original text is odd, keep it.** Archaic spelling, the translator's
  editorial brackets (`⌈⌈and⌉⌉`, `[...]`, `(even)`), `--` for a dash, `. . .` for a
  lacuna, doubled words ("that that"), lettered sub-verses (`6a.`), duplicate verse
  numbers for parallel recensions, verse-numbering gaps the edition really has,
  odd punctuation spacing the printed edition uses: all preserved.
- **If the source we scrape from has a bug, prefer preserving the text.** A typo,
  a misspelling or an odd character that is really on the source page stays. Repair
  a source defect only when it corrupts *structure* rather than wording and the
  intended reading is unambiguous: malformed HTML that truncates a page, a verse
  number rendered as a footnote link, a broken character reference. Even then,
  restore the text; never "improve" it.
- **If our scraper (or the renderer) introduced it, fix it.** Leaked navigation,
  captions or page furniture in verses, verses merged or split wrongly, text
  dropped, notes attached to the wrong verse, double-escaped entities, encoding
  damage we introduced.

Every flag is a question, not a verdict. Most odd things in these texts are genuine.
Do not "fix" something only because it looks strange.

## Workflow

### 1. Render and diff

From the repository root:

```bash
uv run python .agents/skills/osis-text-triage/scripts/triage.py
```

With no arguments it finds every XML under `open-canon-osis-documents/` that differs
from the merge-base with `main` (including uncommitted and untracked files). Pass
file paths to check specific documents, `--base REF` to compare against another ref,
`--out DIR` to keep the output somewhere specific, `--no-diff` to skip the base
render, and `--diff-limit 0` for the full diff.

For each file it prints:

- **Verse count** before and after, and pages added or removed.
- **Rendered-text diff** per page (reading pane and notes tray as plain text, one
  block per line, verse number first). This is the most important output: every
  changed line should be explained by the change you made. Unexpected changes in
  untouched chapters are a red flag.
- **Structural checks** on the XML: duplicate `osisID`s, verse gaps, verse numbers
  going backwards, empty verses, unparsable XML.
- **Heuristic flags** on the rendered text: leftover markup, entities shown as
  text, mojibake (`Â¼`, `â€™`, `�`), site chrome (`Click to enlarge`,
  `[paragraph continues]`, `(See page 214)`, `Next:`), a verse number inside verse
  text (`5 6 And ...`), bare page markers, doubled words, spacing around punctuation.

Plain-text dumps of every page land under `<work dir>/text/{head,base}/` so you can
`grep` or diff them further. A large document (e.g. `old_testament.xml`) produces a
lot of output; narrow it with file arguments and a reasonable `--diff-limit`.

Also look at the pages the diff points to in a browser when layout matters
(poetry line breaks, notes tray alignment, headings):

```bash
python -m http.server --directory <work dir>/head/<document> 8080
```

### 2. Triage each oddity

For each flag or surprising diff line, decide which bucket it belongs in by
checking the source, not by guessing:

1. **Find the scraper.** The README's scraper table maps each XML file to its
   subcommand; `src/open_canon_site/scrapers/registry.py` maps subcommands to
   modules. Or `grep -rn "<file stem>" src/open_canon_site/scrapers`.
2. **Look at the source.** Scraped pages are cached under `.cache/html/` (the
   default `--cache-dir`). Find the page for the chapter in question and read the
   raw HTML around the passage. If it isn't cached, fetch the source page.
3. **Classify:**

   | What you see in the source | Bucket | Action |
   |---|---|---|
   | The odd text is printed that way | Original text | Preserve. Note it as intentional if it might trip up a future reviewer. |
   | The source page has a typo or garbled character | Source bug, wording | Preserve. |
   | The source's markup is broken and our parse loses or misplaces text | Source bug, structure | Fix in the scraper so the text is restored as printed. |
   | The source is fine; our output differs | Scraper bug | Fix in the scraper. |
   | The XML is right but the page shows it wrong | Renderer bug | Fix in `renderer.py` / `parser.py` / templates, not the XML. |
   | Can't tell what the original reads | Unclear | Leave it, and report it to the user with the evidence. |

Triage at the level of the pattern, not the instance: if `( Acts 3:21)` has a stray
space because a link was stripped, every stripped link probably does too.

### 3. Fix in the scraper, never in the XML

- **Never hand-edit files in `open-canon-osis-documents/`.** They are build outputs;
  the next scrape would silently undo a hand edit. All text fixes go into the
  scraper that generated the file (or into a shared helper such as
  `scrapers/_osis.py`, `scrapers/sacred_texts/_layout.py` when the bug is shared).
- Make the fix as narrow as the bug: target the specific markup pattern, so the
  change cannot alter text elsewhere. Prefer recognizing structure over
  string-replacing wording.
- Add a regression test under `tests/scrapers/` using a trimmed real fixture of the
  offending HTML, asserting the exact expected text.
- Regenerate the document from the cache (`uv run open-canon-scrape <scraper> -o
  open-canon-osis-documents`; the cache is used by default) and run this skill
  again. The diff should now show only the intended change. Revert regenerated
  files whose only differences are timestamps.
- Run `uv run pytest` and `uv run ruff check .`.

### 4. Report

Summarize for the user, grouped by bucket:

- **Fixed:** what was wrong, where (document, book, chapter:verse), the scraper
  change, and the before/after text.
- **Preserved on purpose:** odd-but-original things a reviewer might question,
  with the evidence (what the source shows).
- **Unresolved:** anything you couldn't classify, with what you checked.

Reference passages by document and verse (`Letter of Aristeas 1:49`), and give
counts when a pattern affects many verses. In commit messages, follow the
repository's Conventional Commits style (`fix(scrapers): ...`) and say which
documents were regenerated.
